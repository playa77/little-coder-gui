## Standing constraints (apply to every WP)

- Whole cuts, not hiding: if a WP "removes" something but its command/tool/default/execution
  path is still reachable, the WP is not done.
- No `pi` fork or runtime rewrite inside little-coder-gui; keep `pi-sdk-driver` a thin
  adapter as the repo's driver guidelines already require.
- No in-product planning, orchestration, research agents, phase models, or shortcuts to
  enable them (PROJECT-RULES §3). WP-005/007 must include an explicit negative test that
  none of these are reachable.
- Every WP's PR must include its own evidence, in its doc's Evidence section: what ran, on
  what surface, at which tier (unit / core Electron / live / packaged).
- Persistent-data rule (repo AGENTS.md) carries over: never delete session history,
  transcripts, screenshots, or cached artifacts; ask before destructive commands or history
  rewrites.

## Dependency notes (why this order)

WP-002 and WP-003 both sit on WP-001's integration choice — either inline port or CLI-child
bridge changes where the provider registration and extension factories live. WP-004..006
shrink UI only after the runtime underneath has a correct fixed set, so nothing in the UI is
built against a surface that then has to be re-cut. WP-007's live acceptance is last because
only then is what it verifies the true product, not a moving target.
